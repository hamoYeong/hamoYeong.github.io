> 이 글은 C5 설계 과정을 정리한 사용자 검토 전 초안입니다. Learn with AI는 실제 학습자 파일럿 전이며, 교육 효과가 확인된 커리큘럼처럼 표현하지 않습니다.

## 핵심 주장

컴퓨팅 사고력은 중요하다는 말만으로는 학습자가 무엇을 연습해야 하는지 알기 어렵습니다. 그래서 C5에서는 가르칠 지식 목록보다 학습자가 반복할 사고 행동을 먼저 정의하고, 그 행동에 필요한 최소 Swift 개념을 역산했습니다.

## 사용할 수 있는 실제 근거

- 하모컴은 명확한 학습자와 커리큘럼 없이 도구부터 만든 한계 때문에 중단했습니다.
- C4의 1:1 도움에서는 설명할수록 더 기초 개념으로 거슬러 올라갔고, 한 번의 설명이 다시 꺼내 쓸 사고 체계가 되지 못했습니다.
- C5에서 인지 부하, 학습 발판, 메타인지, 자기설명과 전이를 설계 개념으로 검토했습니다.
- 막힘 감지 → 아는 것과 모르는 것 분리 → 위치·조건·시도 언어화 → 질문 생성 → AI 결과 판단이라는 사고 행동을 정의했습니다.
- 필요한 최소 Swift 개념을 사고 행동에서 역산했습니다.
- 비선형 지식 체계와 선형 학습 체계를 분리해 Obsidian, 구현 Ticket과 macOS 프로토타입으로 연결했습니다.
- 현재 결과물은 설계 구조, 프로토타입과 포스터이며 실제 학습자 파일럿은 진행하지 않았습니다.

## 글의 전개 초안

### 1. “컴퓨팅 사고력이 중요하다”는 말이 행동을 만들지 못하는 이유

- 추상적인 역량 이름과 학습자가 실제로 수행하는 행동 사이의 거리를 설명합니다.
- 지식 목록을 많이 아는 것과 처음 보는 문제에서 이전 경험을 연결하는 것을 구분합니다.

### 2. 무엇을 가르칠까에서 어떤 사고를 하게 할까로

- Swift 문법 목록을 먼저 만들려 했던 Before를 씁니다.
- 막힘을 감지하고 질문으로 바꾸는 사고 행위를 먼저 정의한 After를 씁니다.
- 왜 Swift를 사용하는지도 환경이 주어졌다는 이유와 학습 도구의 적합성으로 나누어 설명합니다.

### 3. 사고 행위에서 최소 Swift 개념을 역산하기

- 각 사고 행동에 어떤 Swift 개념이 필요한지 예시 하나를 사용자가 직접 작성합니다.
- 개념을 줄이는 일이 내용을 쉽게 만드는 것과 어떻게 다른지 설명합니다.

### 4. 인지 부하·메타인지·자기설명·전이를 설계에 연결하기

- 인지 부하: 한 번에 다뤄야 할 정보의 크기를 조정
- 메타인지: 이해되지 않는 순간을 포착하고 아는 것과 모르는 것을 구분
- 자기설명: 의도, 가정과 판단 근거를 자신의 말로 표현
- 전이: 이전 경험을 처음 보는 문제에 연결

### 5. 아직은 설계 가설이다

프로토타입을 만들었다는 사실과 학습 효과가 확인됐다는 주장을 분리합니다. 다음 단계는 다양한 초심자와 작은 파일럿을 진행하고, 발판이 답을 유도하는지 질문을 스스로 만들게 하는지 관찰하는 일입니다.

## 아직 답하지 못한 질문

- 컴퓨팅 사고력의 여러 행동 중 첫 파일럿에서 무엇을 가장 먼저 관찰할 것인가?
- 자기설명과 단순한 정답 재진술을 어떻게 구분할 것인가?
- 새로운 문제로의 전이를 어떤 과제로 확인할 것인가?
- 발판이 너무 크거나 작다는 신호를 어떤 행동으로 판단할 것인가?
- Swift가 아닌 다른 도메인에서도 유지되는 사고 행동은 무엇인가?
